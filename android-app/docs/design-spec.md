## 1. 屏幕清单与导航关系

### 1.1 屏幕

| id | 名称 | 是否显示 tabbar | 主要入口 | 返回去向 |
|---|---|---|---|---|
| `chats` | 消息列表 | ✅ 显示 | 启动默认页；tabbar「消息」 | 系统退出 |
| `chat` | 聊天 | ❌ 隐藏 | 点击会话行 / 新聊天 sheet / 个人资料「发消息」 | 返回 `chats`（或来源，见 5.1） |
| `bubbles` | 气泡与主题 | ❌ 隐藏 | 「我」→ 气泡与主题；聊天「更多」→ 气泡与主题 | 回到进入前页面（`me` 或 `chat`） |
| `contacts` | 通讯录 | ✅ 显示 | tabbar「通讯录」 | 系统退出 |
| `profile` | 个人资料 | ❌ 隐藏 | 通讯录行；聊天头部对方信息区 | 回到 `contacts` 或 `chat`（记录来源） |
| `me` | 我 | ✅ 显示 | tabbar「我」 | 系统退出 |
| `call-voice` | 语音通话 | ❌ 隐藏 | 聊天头部电话按钮；个人资料「语音」 | 挂断后回 `chat` |
| `call-video` | 视频通话 | ❌ 隐藏 | 聊天头部视频按钮；个人资料「视频」 | 挂断后回 `chat` |

- tabbar 只在 `chats / contacts / me` 三个根屏幕显示；`chat / bubbles / profile / call-*` 一律隐藏。
- 通话屏幕强制深色 chrome（状态栏图标变白）；返回后恢复主题对应的 chrome。
- 页面切换记忆滚动位置（每个屏幕的滚动容器独立记忆，切回时恢复）。

### 1.3 浮层（覆盖整屏，含状态栏区域）

| 浮层 id | 类型 | 触发 | 关闭方式 |
|---|---|---|---|

### 1.4 系统 chrome（Android 不要自绘）

设计稿外壳中的以下元素是「手机样机」装饰，**Compose 端不得绘制**，用真实系统能力替代：

### 2.7 字体与字重

设计字体栈：`"HarmonyOS Sans SC", "Noto Sans SC", "Source Han Sans SC", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`。

设计稿出现的字重：500 / 550 / 600 / 620 / 640 / 650 / 680 / 700 / 720 / 760 / 780 / 800。系统字体只支持离散字重，建议映射：

| 设计字重 | 建议 Compose |
|---|---|
| 500、550 | `FontWeight.Medium`（500） |
| 600、620、640、650 | `FontWeight.SemiBold`（600） |
| 680、700、720 | `FontWeight.Bold`（700） |
| 760、780、800 | `FontWeight.ExtraBold`（800） |

字母间距（em → Compose `letterSpacing`）：
- appbar 大标题 `-0.02em`
- appbar 小标题 / 个人资料名 / 通话名 `-0.01em`
- 会话时间 `0.01em`；tabbar 标签 `0.02em`；通话状态与视频计时 `0.03em`
- 设置组标题 `0.05em`；通讯录分组标题 `0.06em`

## 5. 交互行为清单

### 5.1 导航与返回

- tabbar 点击切换 `chats / contacts / me`；激活 tab 文字 `accent-text`。
- 会话行 → `openChat(id)`：停止语音播放；`activeId=id`；该会话未读清零；`order = ++orderSeq`；刷新头部（头像 36、名字、副标题、群聊隐藏通话按钮）；渲染消息；显示 chat；滚到底；刷新会话列表；返回按钮获得焦点。
- 聊天返回 → `chats`，焦点回到该会话行。
- 聊天头部对方区 → `profile`（返回目标记为 `chat`）；通讯录行 → `profile`（返回 `contacts`）。
- 个人资料返回 → 记录来源屏幕；`contacts` 时焦点回到对应行，`chat` 时焦点回到聊天头部。
- bubbles 返回/完成 → 回到进入前屏幕（`me` 或 `chat`）。
- Android 返回键：viewer → sheet → dialog → 屏幕返回；通话页行为未定义（见第 10 节）。
- 屏幕滚动位置独立记忆，切回恢复。

### 5.2 搜索

- 消息页搜索行默认收起；点搜索图标展开并聚焦；再次点击不收起（原型只展开）。输入即时过滤：`(name + ' ' + preview)` 小写包含匹配。
- 有输入时显示清空按钮；清空按钮 / 空态按钮都清空输入并重新过滤、聚焦。
- 通讯录搜索常驻；匹配 `(name + ' ' + role)`；清空逻辑同上。
- 无结果时显示对应空态，列表隐藏。

### 5.3 发送与自动回复

- 发送条件：输入 trim 后非空。发送后：清空输入、按钮切回麦克风、重新聚焦输入框。
- 新文本消息：`from=me`，`status` 缺省填「已送达」，`time=当前 HH:mm`；追加到当前会话；`preview = previewOf(msg)`；`conv.time = msg.time`；`order = ++orderSeq`；清未读；重渲染并滚底；刷新列表。
- `previewOf`：
  - text → 原文；
  - image → `图片 · {alt}`；
  - file → `文件 · {name}`；
  - voice → `语音 · m:ss`。
- 任意发送（文本 / 图片 / 文件 / 语音）都会调度一次自动回复（附件发送同样触发）。
- 自动回复时序：
  1. 立即设 `_typing = true`；若正在看该会话：消息列表末尾出现三点气泡、头部副标题变「正在输入…」（`accent-text`）、滚到底。
  2. **1900ms** 后：从回复池按全局计数取文案（见 6.3）；群聊再按全局回复计数奇偶决定发送者：奇数次回复 →「赵敏」，偶数次 →「陈屿」（计数在取文案后 +1，首次回复计数为 1 → 赵敏）。
  3. 追加对方文本消息（带 `who`，群聊用于显示发送者名，单聊 `who = 会话名` 但不显示）；把该会话中所有我方消息 `status` 改为「已读」；`preview`：群聊为 `{who}：{text}`，单聊为 `{text}`；`conv.time = now`；`order = ++orderSeq`；若正在看该会话则移除三点气泡、恢复副标题、重渲染并滚底；刷新列表。
  4. 再次发送会清除并重置该会话的 1900ms 计时器。
- 打开其他会话不影响其他会话的后台回复计时。

### 5.4 未读与排序

- 会话排序：`pinned` 降序优先，其次 `order` 降序。
- `orderSeq` 初值 5；打开会话 +1、发送 +1、自动回复 +1。
- 打开会话 / 发送消息会把该会话未读清零。
- tabbar 合计 = 非静音会话未读之和；>99 显示 `99+`；0 隐藏。
- 静音会话：行内显示灰色徽标，tabbar 不计入。

### 5.5 录音与语音播放

- 进入录音的两种方式：输入区麦克风；附件 sheet 选「语音」。
- 录音开始：计时 `00:00`，每秒 +1；主行隐藏、录音条显示。
- 取消：结束计时，恢复输入区，不生成消息。
- 发送：时长 = `max(1, 已录秒数)`；生成我方语音消息并触发自动回复流程。
- 播放：点击语音气泡切换播放/停止；同一时间仅一条；波形动画 + 图标淡化；到 `duration` 秒自动停止；切换会话或发起通话时停止。

### 5.6 通话

- 发起：聊天头部电话/视频（群聊按钮隐藏，不可发起）、个人资料语音/视频。发起前停止语音播放。
- 进入即「正在呼叫…」、波纹动画开启、所有控件复位（静音/免提/翻转全部关闭、本地画面不翻转）。
- **2400ms** 后接通：停止波纹、`connected=true`、计时从 `00:00` 开始每秒 +1，状态文字变 `mm:ss`。
- 语音页右上 X 与红色挂断等效；视频页红色挂断。
- 挂断：清除计时器、停止语音；**固定回到该会话聊天页**（重新 `openChat`，会清未读并刷新 order）；toast：
  - 已接通：`通话结束 · mm:ss`
  - 未接通：`已取消通话`
- 静音 / 免提：本地切换选中态（无真实音频行为）。
- 视频翻转：切换本地画面镜像与两个翻转按钮的选中态；toast `已切换到前置摄像头`（镜像开）/ `已切换到后置摄像头`（镜像关）。
- 通话页 chrome 强制深色，结束回聊天后恢复主题。

### 5.7 主题与深色

- 所有主题修改即时生效并全局同步（预览、所有聊天气泡、聊天背景、tab/按钮主色）。
- 气泡配色 5 选 1；圆角 3 选 1；字号 3 选 1；背景 3 选 1；深色开关。
- 主题摘要「气泡名 · 圆角名」实时更新到「我」的菜单值。
- 深色开关出现在 bubbles 页与 me 页，两处状态同步；切换时 toast：`已切换到深色模式` / `已切换到浅色模式`。
- 深色只影响应用内主题（不是系统深色跟随；见第 10 节）。

### 5.8 清空聊天

- 入口：聊天头部更多 → 聊天设置 sheet →「清空聊天记录（仅清空当前会话）」→ 确认弹窗。
- 弹窗文案见第 7 节。确认后：清空当前会话消息、`preview='还没有消息'`、`time=''`、`_typing=false`、取消待回复计时；重渲染聊天（显示空态）与列表；toast `聊天记录已清空`。
- 取消只关闭弹窗，焦点回更多按钮。

### 5.9 附件流程

- 图片：按顺序循环取 6.4 的照片（cat → coffee → desk → cat…），直接作为我方图片消息发送（同时触发自动回复）。

### 5.10 图片查看器

- 关闭：右上 ×、点背景空白、返回键；关闭后焦点回触发图片。

- 选择 → 关闭 sheet → 打开对应聊天。

### 5.12 关于 / 通知开关 / 下载

## 9. Android 实现建议

### 9.1 尺寸换算

- 设计画布 412×915，1 CSS px = 1 dp；字号直接用同名 sp 数值（17→17sp）。
- 用 Compose `density` 自适应真实屏宽；所有水平内边距/固定宽度按上表 dp 值，不做百分比缩放（唯一例外：消息栈最大宽 = 行宽 − 86dp；≤380dp 宽时图片消息改 208dp）。
- 建议提供 `@Preview(widthDp = 412, heightDp = 915)` 用于 1:1 比对。

### 9.2 Insets

- 全 edge-to-edge：状态栏与导航栏透明，Appbar/列表/输入区用 `WindowInsets.systemBars` 做 padding。
- 设计稿的「上 52 / 下 28」只是样机近似值，真实值取 insets。
- 底部 sheet 需延伸至导航栏后（surface 铺满），内容区额外 padding 底部安全区；遮罩覆盖状态栏区域。
- 通话页状态栏图标强制浅色（`WindowInsetsControllerCompat.isAppearanceLightStatusBars = false`）。
- 键盘：`adjustResize` + `imePadding()`，输入区随键盘上移；消息列表在键盘弹出时保持贴底。

### 9.3 主题实现

- 用一个可观察的 `ThemeState`（bubblePalette / radius / chatFont / wall / dark）+ DataStore 持久化，全局 `CompositionLocal` 下发。
- 颜色按第 2 节建 `ColorScheme` 扩展（不要直接散落 hex）；气泡相关 5 色、圆角、字号、wall 为独立于 Material 的枚举。
- 深色仅由应用内开关驱动（当前设计），若产品要求跟随系统再改（见第 10 节）。
- 状态栏/导航栏图标明暗随 `dark || isCallScreen`。

### 9.4 字体

- 首选系统默认（中文机型为 Noto Sans CJK / 厂商字体），字重按 2.7 映射。
- 若还原度不足，再评估内置 HarmonyOS Sans SC（需一并打包字重 400/500/600/700/800；注意授权文件与包体增量）。此项见第 10 节。

### 9.5 资源与数据

- 头像/图片资源见第 8 节。
- Mock 数据建议作为 `initial_seed.json` 放 `assets/`，首次启动写入数据库（Room）；后续接后端时以服务端会话为准。
- 时间显示：会话时间由数据提供（`14:32`、`昨天` 等字符串），不做本地化重算；新消息时间取本机 `HH:mm`。

### 9.6 状态与动画

- 输入中三点、语音波形、录音、呼叫波纹用 Compose `rememberInfiniteTransition`；系统「移除动画」开启时停止或降为静态。
- 发送后 1.9s 回复用协程 `delay(1900)`，按会话 Job 管理，切会话不取消；清空聊天时取消该会话 Job。
- 未读/排序状态用单一 `ConversationRepository` 管理，UI 只读。

## 10. 设计稿不明确 / 需 team-lead 决策的点

1. **字体族**：设计指定 HarmonyOS Sans SC 优先。Android 是否内置该字体（包体 + 授权）还是用系统字体 + 字重近似？建议先用系统字体，验收后视还原度再定。
2. **精确字重**：550/620/640/650/680/760/780 无法直接映射；本文档给了近似映射，需确认可接受。
3. **后端接入后是否保留模拟回复**：当前 1.9s 自动回复是演示行为。接入 BN_agent 后应改为真实流式回复；mock 数据是否只做首装种子？建议：首装种子 + 真实后端优先，模拟回复仅在离线/演示模式启用。
4. **通话挂断去向**：设计固定回「该会话聊天页」（即使从个人资料发起，也会跳进 chat）。是否改成返回发起页？
5. **通话页返回键**：设计只处理了 viewer/sheet 的 Esc，未定义通话页返回。建议 Android 返回键 = 挂断（等同红色按钮），需确认。
6. **消息时间戳**：设计气泡不显示每条消息时间，仅日期分隔。接后端后是否需要补「气泡时间」或长按查看？
7. **深色模式是否跟随系统**：设计是应用内手动开关（默认关）。是否需要「跟随系统」三态？
8. **Toast 位置**：设计固定距底 104dp，在通话/详情页（无输入区）也如此。是否按屏幕调整？
9. **「图片」附件来源**：设计循环使用 3 张内置图。Android 是否改为系统相册选择器（需权限/Photo Picker）？演示可先沿用内置图。
10. **文件下载 / 语音播放 / 通话**：均为演示行为（下载只 toast、无真实音频/通话）。Android 端是否保持纯演示，还是接入真实文件保存/音频播放？
11. **群聊未读徽标**：设计静音群聊仍显示灰色行内徽标但不计入 tab 总数；确认这是产品预期。
12. **置顶能力**：数据含 `pinned`，但 UI 无置顶/取消置顶入口。是否需要补充长按菜单？
